# LLM 품질 루프 결정 기록

## DEC-001: 기존 저장소에서 작업

- 결정: 새 저장소를 만들지 않고 `C:\National_Assembly_3`에 추가한다.
- 이유: 기존 제품 코드와 같은 Git 이력에서 품질 개선 과정을 보여주기 위함이다.

## DEC-002: 신규 평가 v2 격리

- 결정: 기존 `data/eval`과 기존 평가 스크립트를 신규 점수 계산에 사용하지 않는다.
- 이유: 기존 평가의 오판과 데이터 오염 가능성을 새 평가에 전달하지 않기 위함이다.
- 허용: 원문 PDF, 데이터베이스, 현재 `/query` 시스템의 수정 전 답변.

## DEC-003: RRF 변경 보류

- 결정: 이번 3일에는 RRF를 수정하지 않는다.
- 이유: 생성 및 검증 문제를 먼저 분리해서 측정하기 위함이다.

## DEC-004: 실패 우선 판정

- 결정: 평균 점수가 높아도 치명적인 거짓 답변이 한 건이면 실패다.
- 이유: 국회 회의록 답변은 인물, 날짜, 위원회, 숫자 오류의 위험이 크기 때문이다.

## DEC-005: Codex 단독 QA 역할 분리

- 결정: 별도 에이전트를 만들지 않고 Codex가 개발·QA·채점·감사 단계를 순서대로 수행한다.
- 이유: 사용자가 새 에이전트 생성을 취소했으며, 한 실행 안에서 코드 수정과 QA 판정을 섞지 않기 위함이다.

## DEC-006: 포트폴리오 최종 기준 고정

- 결정: 전체 의미 정확도 90%, 인용 정확도 95%, 답변 불가 거절 100%, 근거 없는 주장 0건을 모두 요구한다.
- 이유: 결과를 본 뒤 합격선을 낮추는 목표 이동을 막고, 엄격한 포트폴리오 품질을 유지하기 위함이다.

## DEC-007: 모든 신규 문제와 해결 증거 누적

- 결정: 새 문제는 `QA_ISSUES.md`에 등록하고 재현 테스트·수정·전체 회귀까지 기록한다.
- 이유: 같은 문제를 반복 수정하거나 해결되지 않은 문제를 완료로 오인하지 않기 위함이다.

## DEC-008: 단계별 게이트와 데이터 수명주기 적용

- 결정: G0 데이터부터 G7 최종 블라인드까지 앞 단계가 실패하면 다음 단계를 실행하지 않는다.
- 결정: 예비와 최종 블라인드는 정해진 횟수만 사용하고 사용 후 개발셋으로 이동하거나 폐기한다.
- 이유: 검색·생성·검증 오류를 섞어 수정하는 것과 이미 본 문제에 과적합하는 것을 막기 위함이다.

## DEC-009: 채점기 역시 QA 대상

- 결정: 결정 채점과 의미채점 불일치는 자동 PASS가 아니라 재검토 대상으로 처리하고, 채점기 변경은 새 버전으로 기록한다.
- 이유: 시스템 답변뿐 아니라 채점 오탐도 점수를 왜곡한 실제 사례가 있었기 때문이다.

## DEC-010: 사용자 경로와 평가 경로 동등성 필수

- 결정: 실제 UI 경로와 평가 API가 같은 라우터·검색·프롬프트·모델·검증 설정을 쓴다는 통합 테스트 없이는 최종 점수를 제품 성능으로 발표하지 않는다.
- 이유: 평가 경로만 좋아지고 실제 사용 경로는 다른 상태를 막기 위함이다.

## DEC-011: 질문 필수값과 참고값 분리

- 결정: 자동 누락 실패는 질문이 직접 요구한 `required_exact_values`에만 적용하고, 원문 참고값은 별도로 저장한다.
- 이유: 질문이 요구하지 않은 조문·날짜·숫자를 답하지 않았다는 이유로 정상 답변을 감점하지 않기 위함이다.

## DEC-012: 인용 성공은 정확한 근거 chunk로 판정

- 결정: 같은 회의록 `source_id`의 다른 조각은 gold 인용 성공으로 인정하지 않는다. `gold.evidence[].chunk_id`와 실제 인용 `chunk_id`가 일치해야 한다.
- 이유: 같은 문서의 앞 조각만 인용하고 뒤 조각의 정답을 생성한 `blind-021`을 기존 문서 단위 채점이 통과시켰기 때문이다.

## DEC-013: portfolio 코드 기준을 90/95/100/0으로 통일

- 결정: `portfolio` 프로필도 전체 90%, 인용 95%, 답변 불가 거절 100%, 치명 오류 0을 사용한다.
- 이유: 문서상 고정 목표보다 낮은 85/90/90 임시 기준이 코드에 남아 거짓 PASS를 만들 수 있었기 때문이다.
