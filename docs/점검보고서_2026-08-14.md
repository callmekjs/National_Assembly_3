## 제일 궁금해한 것부터 — 데이터, 믿을 수 있나?

**결론: 생각보다 훨씬 건강하다.** 검사관들이 표본을 뽑아 눈으로 다 봤는데:

- 회의록 767건이 모든 가공 단계에 빠짐없이 존재. 단계 사이 유실 없음
- 깨진 한글 0건, PDF 찌꺼기(쪽번호·머리글) 0건
- 임베딩(검색용 숫자 변환) 빠진 청크 0건, 중복 0건
- 배포 서버의 숫자(767건 / 50,726청크 / 512차원)가 README 주장과 정확히 일치
- 의원-정당 연결 표본 검사 통과 (한자 이름, 동명이인 방어도 작동)

**다만 진짜 문제가 3개 나왔다.** 셋 다 "데이터가 오염된" 게 아니라 **"PDF를 읽는 단계에서 생긴" 문제**다.

### 데이터 문제 1 — 발언 125건이 소리 없이 증발했다 🔴

- [scripts/parser_v1.py:81](../scripts/parser_v1.py)에 **오타 하나**가 있다. 주석(설명 메모) 뒤에 줄바꿈이 잘못 들어가서, "대변인·검사·교수"를 알아보는 규칙이 **통째로 꺼져 있다.**
- 그래서 국방부 대변인, 대검찰청 검사, 청문회에 나온 교수의 발언 **약 125건이 "발언자를 모르겠다"며 버려졌다.**
- 실제 확인: 쿠팡 해킹 청문회의 전문가 증언 32건+, 국방부 대변인 전하규 — **배포 서버에서 검색하면 0건.**
- 덤으로 나쁜 것: 버려진 자리를 건너뛰고 번호를 매겨서, **"앞뒤 발언" 연결이 어긋난 곳**이 생겼다.
- **고치기: 오타 한 줄 수정 + 데이터 재가공.** 코드는 1분, 재가공은 시간이 걸린다.

### 데이터 문제 2 — 회의록 끝의 "명단 표"가 발언으로 둔갑했다 🟡

- 회의록 PDF 끝에는 발언이 아닌 **부록**(안건 목록, 위원 명단, 증인 명단 표)이 붙는다.
- 파서가 이걸 발언으로 착각해서, 배포 서버에 **"관련의안"이라는 유령 발언자** 청크 21건과,
  **실존 의원 10명 이름에 명단 표 조각이 발언처럼 붙은** 청크가 들어가 있다.
- 예: "박성민 의원 발언"을 찾으면 명단 표 조각이 근거로 나올 수 있다.
- 주의: 같은 부류로 보이는 것 중 약 30건은 **진짜 발언**(발언대 진술인)이라, 뭉텅이로 지우면 안 되고 골라내야 한다.

### 데이터 문제 3 — "산회합니다" 뒤의 증인 명단이 위원장 발언에 붙었다 🟡

- 위원장이 폐회를 선언한 뒤 붙는 증인 명단 표가 **위원장 발언 텍스트 안에 병합**됐다. 배포 서버에 8건.
- "최민희 위원장이 뭐라고 했나" 물으면 답 근거에 증인 27명 명단이 섞여 나올 수 있다.

**데이터 총평: 뼈대는 건강하고, PDF 읽기 단계의 흠 3개만 고치면 된다.** 네 직감(데이터가 의심된다)은 절반 맞았다 — 문제는 있었는데, 네가 걱정한 "전체가 부실한" 종류가 아니라 "특정 지점 3곳"이었다.

### 🔴 3. 돈이 새는 뒷문이 열려 있다

### 🔴 4. "근거 카드"가 실제보다 부풀려 말한다

- 답변 옆의 신뢰 카드가 FULL 등급이면 무조건 **"문장 전부가 근거에 연결됨 5/5"** 라고 표시한다.
- 그런데 실측해 보니 **최근 FULL 답변 10개 중 9개에 근거 없는 문장이 섞여 있다.**
  심한 예: 47문장 중 21문장만 인용이 있는데 화면엔 "47/47".
- 이 프로젝트의 자랑이 "근거 없으면 지어내지 않는다"인데, **카드가 시스템이 실제 확인한 것보다 세게 보증**하고 있다. 사용자가 눈치채는 순간 신뢰가 무너지는 종류의 문제.
- **고치기: 실제 센 숫자를 그대로 보여주거나, 문구를 "인용이 모두 유효함" 수준으로 낮추기.** ([frontend/src/components/AnswerPanel.jsx](../frontend/src/components/AnswerPanel.jsx))

## 곧 고치면 좋은 것 (노란불)

- **서버가 스스로를 잠글 수 있다** — 시작 직후 DB가 잠깐 삐끗하면, 잘못된 값(1536차원)을 **영구 기억**해서 재시작 전까지 모든 질의가 500 오류. 무료 서버는 매일 잠들었다 깨니 조건이 자주 온다. ([backend/search_vector.py:39](../backend/search_vector.py))
- **부록 오염 청소** (위 데이터 문제 2·3)
- **뒤로가기가 안 먹는다** — 쟁점 상세에서 뒤로가기하면 주소는 목록인데 화면은 상세 그대로.
- **잠든 서버에 공유 링크로 들어오면 첫 화면이 실패한다** — 깨는 데 30초+ 걸리는데 20초 만에 포기하고, 깬 뒤에도 스스로 다시 시도하지 않는다. 새로고침해야만 산다.
- **PARTIAL 수치도 계산이 틀린다** — 문장 세는 규칙이 인용 붙는 위치와 어긋나서, 실제보다 나쁘게(3/7처럼) 표시된다. 4번과 반대 방향의 거짓말.
- **쟁점을 빠르게 바꾸면 이전 쟁점 데이터가 새 화면에 남을 수 있다** (늦게 도착한 응답이 덮어씀).
- **정정본이 반영 안 되는 구조** — 국회가 회의록 정정본을 올리면 첫 단계만 새로 읽고, 뒷단계들은 "이미 결과 있네" 하고 건너뛴다. 지금 실제 발생 사례는 0건이지만 구조상 언젠가 터진다.
